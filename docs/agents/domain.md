# Domain docs

This repo uses a single-context layout:

- `GLOSSARY.md` defines domain vocabulary.
- `docs/adr/` records architectural decisions.

## Before exploring

Read the glossary and ADRs relevant to the area being explored.
If either is absent, proceed silently. Create domain documents
through domain-modeling when terms or decisions are resolved.

## Vocabulary

Use glossary terms in code, tests, issues, and proposals.
Raise conflicting definitions or missing domain concepts
through domain-modeling.

## Decisions

Surface conflicts with existing ADRs explicitly, citing
the relevant ADR and explaining why it should be reconsidered.
